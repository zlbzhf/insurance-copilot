# Expected Eval Output — AIA Public Pack Source-Backed Update

## Required Behaviors

- Use **Institution Knowledge Organizer** for the **AIA public pack** when the task is a **source-backed public pack update**.
- Start from a public **source record** with source URL, source type, retrieved date, public-source flag, and redistribution mode.
- Preserve the **public/private boundary**: public source summaries may enter `knowledge/institutions/aia/`; private customer files, agent notes, production exports, and non-public institution material must stay outside the public repo.
- Mark currentness, claim-type forms, policy terms, deadlines, and review status with `[verify]` when the official source must be checked again.
- State **No customer data** in the public pack contribution.
- Require **pack maintainer review** before treating the proposed source record or page as canonical.
- For claims pages, state that the summary is not a final claims decision and does not promise approval, payment, coverage, or timing.
- Run the knowledge-pack validator and include validation status before handoff.

## Avoid

- Treating public FAQ text as policy contract language.
- Mixing private workspace materials into the public AIA pack.
- Marking customer-facing copy as approved to send.
- Making a final regulated, underwriting, coverage, or claims conclusion.
